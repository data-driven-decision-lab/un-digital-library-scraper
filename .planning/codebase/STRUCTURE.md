## Directory Purposes

**src/un_data_pipeline/:**
- Purpose: ETL orchestration (scraping, tagging, scoring, aggregation)
- Contains: Python modules implementing three-stage pipeline
- Key files: `scraper_pipeline.py` (2362 lines), `dashboard_data_pipeline.py` (1014 lines)

**src/un_data_pipeline/data_modules/:**
- Purpose: Static reference data for classification and geo-tagging
- Contains: Dictionaries mapping country names to ISO codes, subject tags, geographic hierarchies
- Key files: `un_classification.py` (UNBIS taxonomy), `un_geo_hierarchy.py` (UN regions), `iso2_country.py` (country codes)

**src/un_report_api/app/:**
- Purpose: REST API server for consuming scraped and processed data
- Contains: FastAPI application, response models, business logic services
- Key files: `main.py` (FastAPI app), `report_generator.py`, `ranking_generator.py`, `services/` modules

**src/un_report_api/app/required_csvs/:**
- Purpose: Database fallback files generated by dashboard pipeline
- Contains: Three CSV files updated every pipeline run (annual_scores, topic_votes_yearly, pairwise_similarity_yearly)
- Used by: API when Turso database unavailable (offline/fallback mode)

**src/un_report_api/app/services/:**
- Purpose: Modular business logic for data analysis and report generation
- Contains: Data loaders, ranking calculations, Security Council analysis, LLM-based research code
- Note: LLM services (llm/ subdirectory) are research-phase code, not used in production endpoints

**db/:**
- Purpose: Database schema definition
- Contains: Single file `schema.sql` with DDL for 6 Turso tables
- Note: Applied manually or via Cloud Build at deployment time

**data/reference/:**
- Purpose: Static mapping data used during processing
- Contains: CSV file mapping country ISO3 codes to UN regions
- Used by: Dashboard pipeline `generate_combined_index()` for Pillar 2 calculation

**docs/:**
- Purpose: Architecture and methodology documentation
- Contains: Schema reference, pillar score formulas, API usage examples
- Key files: `SCHEMA.md` (table definitions), `METHODOLOGY.md` (score computation)

**logs/:**
- Purpose: Runtime execution logs
- Contains: Rotating log file from scraper/tagger execution
- Location: `logs/un_scraper_tagger.log` (created at runtime)

## Naming Conventions

**Files:**
- Python modules: `snake_case.py` (e.g., scraper_pipeline.py, dashboard_data_pipeline.py, report_generator.py)
- Data files: `UPPERCASE_WITH_UNDERSCORES.csv` (e.g., UN_Country_Region_Mapping.csv)
- Logs: `lowercase_underscore.log` (e.g., un_scraper_tagger.log)

**Functions:**
- Lowercase with underscores: `get_turso_connection()`, `process_resolution()`, `generate_annual_scores()`
- Entry points named `main()` by convention
- Helper/private functions prefixed with `_`: `_expand_vote_data()`, `_send()` (in TursoHTTPConnection)

**Variables:**
- Lowercase with underscores: `current_run_id`, `existing_links`, `batch_rows`, `df_filtered`, `new_df`
- Constants: UPPERCASE (BASE_SEARCH_URL, DEFAULT_MODEL, MAX_WORKERS, SESSION_RESET_THRESHOLD)
- Global state: `scraper_log_data`, `current_run_id` (avoid where possible; used for logging metadata)

**Classes:**
- PascalCase: `DuplicateLinkFound`, `LocationClassifications`, `ResolutionTarget`, `TursoHTTPConnection`, `TursoCursor`
- Pydantic models for API: `ReportResponse`, `YearlyRankingsResponse`, `SecurityCouncilTopicResponse`

**Database Objects:**
- Tables: lowercase with underscores: `un_votes_raw`, `un_votes_with_sc`, `annual_scores`, `topic_votes_yearly`, `pairwise_similarity_yearly`, `pipeline_runs`
- Columns: CamelCase or quoted strings for special formatting: `"Pillar 1 Score"`, `"Overall Rank"`, `CosineSimilarity`

## Where to Add New Code

**New Feature (Scraper Enhancement):**
- Scraper logic: `src/un_data_pipeline/scraper_pipeline.py`
- Data module: `src/un_data_pipeline/data_modules/` (if adding new classification/hierarchy)
- Tests: Create `src/un_data_pipeline/tests/test_scraper.py` (test framework not yet established)

**New API Endpoint:**
- Endpoint definition: `src/un_report_api/app/main.py` (FastAPI route)
- Response model: `src/un_report_api/app/models.py` (Pydantic schema)
- Business logic: `src/un_report_api/app/services/` (new service module if complex)
- Example: `/sc/veto_analysis` at main.py line ~420, uses `simple_veto_endpoint.py`

**New Pipeline Stage:**
- Core logic: Create new file in `src/un_data_pipeline/` (e.g., `new_pipeline_stage.py`)
- Integration: Call from appropriate main() function (scraper or dashboard)
- Database writes: Use shared `get_turso_connection()` and follow existing save_data_to_turso() pattern

**Utilities (Shared Helpers):**
- Location: `src/un_report_api/app/services/` (for API-related utilities)
- Or: Create `src/un_data_pipeline/utils.py` (for pipeline-related utilities)
- Import: `from src.un_data_pipeline.utils import helper_function`

**Reference Data:**
- Static dictionaries: `src/un_data_pipeline/data_modules/` (new Python file with data structure)
- CSV files: `data/reference/` (for large mappings or external data)
