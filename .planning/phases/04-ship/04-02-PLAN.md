  <action>
    Create `docs/` directory if it does not exist. Write `docs/METHODOLOGY.md` explaining the pipeline computation methodology. The document must cover:

    **Section 1: Overview**
    - What the pipeline produces: annual_scores, topic_votes_yearly, pairwise_similarity_yearly
    - Data source: un_votes_with_sc Turso table (Security Council resolutions filtered out — rows where Resolution starts with "S/")
    - Each country-year combination with zero votes is excluded from all outputs (PIPE-03)

    **Section 2: Pillar 1 — Policy Consistency Score**
    - Purpose: Measures how consistently a country votes within its declared policy positions over time
    - Tag parsing: Only UNBIS Main Category and Subcategory tags are used as `tag_group` (not Specific Items). `parse_tags_for_subtag1()` returns all matching tags from both levels.
    - Rolling window: `bloc_size_p1 = 4`. For a given year Y, the bloc is years [Y-3, Y-2, Y-1, Y]. This means P1 scores begin 3 years after the first year of data.
    - Consistent tags filter: only tags that appear in ALL 4 years of the bloc are used for scoring
    - Weighted deviation formula (per consistent tag group T):
      - `avg_pct[v]` = percentage of votes for outcome v (YES/NO/ABSTAIN) across the full 4-year bloc
      - For each year in the bloc: `yearly_raw_deviation = sum(|year_pct[v] - avg_pct[v]|)` across all 3 vote outcomes
      - `yearly_deviation_normalized = yearly_raw_deviation / 200.0` (divides by max possible deviation of 200)
      - `weighted_deviation[T] = mean(yearly_deviations) * total_votes[T]`
    - Final score: `P1 = max(0, 1 - sum(weighted_deviations) / total_votes_consistent_tags) * 100`
    - Min-max normalization: P1 Score is min-max normalized per year to 0-100 range. "Pillar 1 Score" in annual_scores IS the normalized value.

    **Section 3: Pillar 2 — Regional Alignment Score**
    - Purpose: Measures how closely a country votes with its UN regional bloc
    - Region mapping: `data/reference/UN_Country_Region_Mapping.csv`
    - Two sub-metrics per country per year:
      - **BMM (Bloc Majority Match)**: % of resolutions where the country voted with the regional majority (ties excluded)
      - **BDS (Bloc Directional Similarity)**: cosine similarity of the country's vote percentage vector [YES%, NO%, ABSTAIN%] vs. the regional bloc's aggregate vote percentage vector, scaled to 0-100
    - `P2 = mean(BMM, BDS)` (simple average of both sub-metrics)
    - Min-max normalized per year to 0-100. "Pillar 2 Score" in annual_scores IS the normalized value.

    **Section 4: Pillar 3 — Global Alignment Score**
    - Purpose: Measures how closely a country votes with the global majority across all UN members
    - Same formula as Pillar 2 but using global vote counts instead of regional:
      - **GMMC (Global Majority Match Count)**: % of resolutions where the country matched the global majority vote
      - **GDSC (Global Directional Similarity)**: cosine similarity vs. global vote percentage vector, scaled to 0-100
    - `P3 = mean(GMMC, GDSC)`
    - Min-max normalized per year to 0-100. "Pillar 3 Score" in annual_scores IS the normalized value.

    **Section 5: Total Index**
    - `Total Index Average = mean(P1_Normalized, P2_Normalized, P3_Normalized)` per country per year
    - `Total Index Normalized = Total Index Average` (no second normalization — already on 0-100 scale)
    - `Overall Rank`: rank descending by Total Index Average within each year (rank 1 = highest score)
    - `Overall Rank Rolling Avg (3y)`: 3-year rolling mean of Overall Rank per country

    **Section 6: Pairwise Similarity**
    - Vote encoding: YES=1, NO=-1, ABSTAIN/null=0
    - Cosine similarity computed between every country pair using sklearn's `cosine_similarity` on the encoded vote matrix
    - Countries with all-zero vote vectors (no actual votes cast) are excluded before computation
    - Only pairs where Country1 < Country2 (alphabetical) are stored to avoid duplicates
    - Values stored at full float precision — no rounding applied

    Format the document in Markdown with headers matching the sections above. Include a brief "How to read the scores" note: all pillar scores are 0-100, higher is better, and scores are relative to the cohort in each calendar year (not absolute).

  <action>
    Write `docs/SCHEMA.md` documenting all 6 Turso tables from `db/schema.sql`. For each table include: purpose, how data gets there, and a column reference table.

    **Table 1: un_votes_raw**
    Purpose: Raw scraper output before Security Council tagging. One row per UN resolution.
    Populated by: `scraper_pipeline.py`

    | Column | Type | Description |
    |--------|------|-------------|
    | id | INTEGER | Auto-increment primary key |
    | Resolution | TEXT | Resolution identifier (e.g., `A/RES/79/1`) |
    | Date | TEXT | Voting date in ISO format (YYYY-MM-DD) |
    | Title | TEXT | Resolution title text |
    | Link | TEXT UNIQUE | Source URL on digitallibrary.un.org |
    | tags | TEXT | Comma-separated UNBIS subject tags |
    | vote_data | TEXT | JSON blob: `{"ISO3": "YES"\|"NO"\|"ABSTAIN"\|null, ...}` |

    **Table 2: un_votes_with_sc**
    Purpose: Enriched voting data including Security Council resolutions. Main source table for dashboard pipeline.
    Populated by: `scraper_pipeline.py` after SC tagging
    Identical schema to `un_votes_raw` with one additional column:

    | Column | Type | Description |
    |--------|------|-------------|
    | sc_flag | INTEGER DEFAULT 0 | 1 if Security Council resolution (Resolution starts with "S/"), else 0 |

    Note on vote_data: The JSON blob stores all ~190 country ISO3 codes as keys. Null means the country did not participate (non-member or non-voting). The dashboard pipeline expands this blob into per-country columns at load time.

    **Table 3: annual_scores**
    Purpose: Per-country per-year pillar scores, ranks, and vote counts. Primary table for API report and rankings endpoints.
    Populated by: `dashboard_data_pipeline.py`
    UNIQUE constraint: (Year, Country)

    Document all columns: Year, Country, Pillar 1/2/3 Score (= normalized 0-100 value), Total Index Average, Overall Rank, Overall Rank Rolling Avg (3y), Total Index Normalized, Pillar 1/2/3 Normalized, Pillar 1/2/3 Rank, Yes/No/Abstain/Total Votes in Year.

    Note: "Pillar X Score" == "Pillar X Normalized". Both columns hold the min-max normalized score. The raw pre-normalization score is not persisted.

    **Table 4: topic_votes_yearly**
    Purpose: Per-country per-year per-topic vote counts. Used for topic analysis in reports.
    Populated by: `dashboard_data_pipeline.py` `generate_topic_votes()`
    UNIQUE constraint: (Year, Country, TopicTag)

    Columns: Year, Country, TopicTag (UNBIS Main Category or Subcategory name), YesVotes_Topic, NoVotes_Topic, AbstainVotes_Topic, TotalVotes_Topic

    **Table 5: pairwise_similarity_yearly**
    Purpose: Cosine similarity between every country pair for each year. Used for ally/enemy analysis and regional alignment.
    Populated by: `dashboard_data_pipeline.py` `generate_similarity_matrix()`
    UNIQUE constraint: (Year, Country1, Country2)

    Columns: Year, Country1 (ISO3, alphabetically first), Country2 (ISO3, alphabetically second), CosineSimilarity (REAL, range -1.0 to 1.0, full precision — no rounding)

    Note: Only pairs where Country1 < Country2 are stored. To query alignment between two countries, query with the alphabetically-lower code as Country1.

    **Table 6: pipeline_runs**
    Purpose: Execution metadata for each pipeline run. Enables monitoring and debugging.
    Populated by: both `scraper_pipeline.py` and `dashboard_data_pipeline.py`

    Columns: run_id (UUID), pipeline_name (scraper_pipeline or dashboard_data_pipeline), started_at (ISO datetime), finished_at (ISO datetime), status (running/success/failed), rows_affected, error_message, notes (JSON blob for scraper-specific metrics)

    Format the document in Markdown. Include a brief intro explaining the database is a LibSQL (Turso) database compatible with SQLite DDL, and reference `db/schema.sql` for the authoritative DDL.
